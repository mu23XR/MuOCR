# MuOCR

独立 Android OCR 工具，将大型扫描 PDF 转为可搜索 PDF。中文、英文识别后，在原始页面追加不可见文字层，保留扫描页面的可见内容。

本项目从 [mu23XR/munote](https://github.com/mu23XR/munote) 的 MuOCR 1.1.3 模块独立提取，来源提交为 `91bb4bb480886b0582a2a33ff540024447fcc558`。此仓库仅包含 MuOCR，不依赖 MuNote 应用。

## v1.1.8：混排字体与批量清缓存

- 同一行可分段使用中文、英文和数学符号字体，复用当前 PDF 批次已打开的字体。字体覆盖仍取决于设备；缺字时明确显示页码、字符和 Unicode 编码并保留 OCR 缓存，不以空格替代文字。
- 导出时清除控制/零宽格式字符、规范 Unicode 空白，保留原文/简体选项及原始 OCR 页。升级后旧文字层导出断点会重建一次，已识别的页无需重识别；新断点可继续接续。
- 缓存页增加「清理已完成/取消」与「清理全部可清理」入口，显示数量并确认。整批清理与重试互斥，保护排队/运行和输出待核对任务；部分失败明确列出已清数量，可重试。清理后丢失所选缓存的续做进度，原 PDF、已导出的 PDF 与字体保留。
- 构建在项目 `.gradle/muocr-fonts` 保存按原锁定哈希校验的字体副本，避免失败重试重复下载；下载临时文件不进入 APK。主页版本号读取实际安装包。
- 正式 Gradle 单测119项（基线106，新增13）及 Release/lintVital通过；MuMu1混排输出、覆盖升级、缺字与批量清理证据见 [MUOCR-008](docs/work-items/MUOCR-008.md)。完整 lint仍有6项既有 RestrictedApi错误，用户原395页/1GB实机验收尚未完成。未改识别引擎，不作整体准确率提升承诺。

## v1.1.7：缓存管理、旧版接续与简体文字层

- 主页面进入「缓存管理」，可查看每份缓存的页记录数、文件大小及实际路径，手动清理 OCR 页、PDF 工作副本和临时文件。清理需要确认，运行中及输出待核对的任务受到保护；清理失败会明确提示并留下可重试标记。
- 新任务默认启用「简体中文文字层」，例如旧缓存中的“选择題 ”导出为“选择题”；这是离线简繁转换，不是对所有错字的识别纠正。繁体文档可关闭。排队、暂停或失败的旧任务可点击「改为简体／改为原文」，保留 OCR 页并按需重写文字层。
- 0.1.3 起的五列 OCR 页格式兼容，覆盖升级保留缓存。通过原来的文件提供方重新选择未改动的同一个原 PDF，可接续旧单文件缓存；迁移中断后会补齐缺页，旧缓存保留至手动清理。成功任务的当前工作缓存仍自动清理。
- 缓存通常位于 `Android/data/dev.munote.ocrtool/files/muocr-work`，备用位置在应用内部 `files/muocr-work`，以缓存管理显示的实际路径为准。Android 可能限制文件管理器直接访问。内置字库、原 PDF 和已导出的 PDF 不属于这个清理范围。
- 保持包名及原签名，直接覆盖安装；不要卸载或清除应用数据。清理某任务后会丢失该任务的续做进度，重新处理会从头识别，且不会偷偷重新导入已放弃的旧缓存。
- 正式 Gradle 单元测试106项通过；模拟器缓存/升级/导出验证及完整 lint 的既有问题见 [MUOCR-006](docs/work-items/MUOCR-006.md)。用户提供截图对应的395页原文件尚未实测。

- 平衡模式对低把握页面最多补充一次高分辨率识别，仅采用完整行框匹配且置信度有明显提升的行；高精度模式保留原有高分辨率识别。

## 功能

- 多选导入 PDF，按原文件名生成 `_OCR.pdf`，同名自动编号。
- 严格串行后台队列，支持单文件和全局暂停、继续、取消及重试。
- 每个文件独立保存逐页 OCR 缓存和 PDF 增量导出断点。
- OCR 与 PDF 导出分阶段执行，逐页渲染，默认每批最多 16 页写入 PDF。
- 内置经过固定提交和 Git blob 校验的 Noto Sans SC 中文 TrueType 字体。

Android 10（API 29）及以上。应用包名仍为 `dev.munote.ocrtool`。

## 构建和测试

需要 JDK 17 或以上、Android SDK Platform 36 和 Gradle 8.11.1。通过 `ANDROID_HOME` 或本地 `local.properties` 配置 SDK 路径。

```sh
gradle :ocrtool:testDebugUnitTest
gradle :ocrtool:assembleRelease
```

APK 位于 `ocrtool/build/outputs/apk/release/ocrtool-release.apk`。构建首次需要联网下载已有 Maven 依赖和约 17MB 的固定版本字体。CI 自动运行单元测试、完整Lint、构建APK、校验签名并生成摘要；默认不上传产物，也不会在每次提交时自动发布版本。

为兼容已安装的 MuOCR，保留原应用包名及签名证书。`signing/muocr-legacy-test.keystore` 是上游已经公开的测试密钥，仅用于保持现有升级兼容；它不是私密生产凭证。升级时请勿卸载或清除应用数据，以保留任务断点。
